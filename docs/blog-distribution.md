# Blog Distribution Contract

RonnieCC is the canonical Blog content hub. Subsites should consume the static
Blog package generated by this repository instead of reading Notion directly.

## Source Of Truth

The upstream editor is the public Notion Blog database. RonnieCC syncs that
database into:

- `content/blog.seed.json`
- `content/blog-assets/<post-id>/`

`content/blog.seed.json` is the contract between RonnieCC and product subsites.
RonnieCC always publishes every public post to the main site. Subsite publishing
is additive metadata.

## Notion Fields

| Field | Type | Meaning |
| --- | --- | --- |
| `Name` | title | Article title. |
| `SEO Slug` | text | Required stable English URL slug body for drafts and public posts. RonnieCC appends the post id prefix and uses it for canonical URLs. |
| `Tag` | select / text | Display and keyword metadata. It is not routing metadata. |
| `公開` | checkbox | Global publish gate. If false, no site should publish the post. |
| `編寫日期` | date | Preferred article date and year source. |
| `年份` | formula / text | Fallback year grouping source. |
| `子站點` | multi-select | Extra product subsites that should mirror the post. RonnieCC is implicit and should not be listed here. |

The first supported `子站點` option is `aDict`. It is normalized to the stable
subsite id `adict` in the generated JSON.

## Generated Post Fields

Every public post in `content/blog.seed.json` has the existing Blog fields plus
distribution metadata:

```json
{
  "id": "35fc1b36c40180b88fe2e8fa4e55d6ec",
  "slug": "adict-3-0-rewrite-35fc1b36",
  "seoSlug": "adict-3-0-rewrite",
  "legacySlugs": ["adict-3-0-一個老詞典-app-的重寫-35fc1b36"],
  "title": "aDict 3.0 一個老詞典 App 的重寫",
  "public": true,
  "subsites": ["adict"],
  "publishTargets": ["ronniecc", "adict"],
  "canonical": {
    "site": "ronniecc",
    "url": "https://ronniewong.cc/blog/adict-3-0-.../"
  },
  "content": {
    "source": "notion-v3-page-blocks",
    "syncedAt": "2026-05-20T00:00:00.000Z",
    "blocks": []
  }
}
```

Compatibility rules:

- Missing `subsites` means `[]`.
- Missing `publishTargets` means `["ronniecc"]`.
- Missing `legacySlugs` means `[]`.
- Missing `canonical.url` should be reconstructed as
  `https://ronniewong.cc/blog/${encodeURIComponent(post.slug)}/`.

## Subsite Consumer Rules

A subsite should:

1. Read RonnieCC `content/blog.seed.json`.
2. Filter public posts with its own stable subsite id.
3. Render the filtered posts with its own templates, navigation, footer, and
   product calls to action.
4. Set each mirrored article canonical to `post.canonical.url`.
5. Copy or otherwise serve the referenced `content/blog-assets/` files.
6. Include only mirrored subsite URLs in the subsite sitemap.

Example filter for the aDict subsite:

```js
const subsiteId = "adict";
const posts = blogData.posts.filter((post) => {
  const subsites = post.subsites || [];
  return post.public !== false && subsites.includes(subsiteId);
});
```

Example canonical:

```html
<link rel="canonical" href="https://ronniewong.cc/blog/adict-3-0-.../">
```

## Asset Handling

Blog block image assets use repo-relative paths such as:

```json
{
  "type": "image",
  "assetPath": "content/blog-assets/<post-id>/<block-id>-image.png"
}
```

The preferred subsite implementation copies the needed files into the subsite
repository during its sync step and rewrites paths for the subsite output. This
makes the subsite deploy self-contained and avoids runtime dependency on
RonnieCC static asset paths.

## Boundaries

Subsites should not:

- Query Notion directly for Blog posts.
- Treat `Tag` as routing metadata.
- Require authors to select `ronniecc` in Notion.
- Generate their own slug for mirrored posts.
- Override the canonical URL for fully mirrored articles.

RonnieCC owns content normalization, stable slugs, Notion block snapshots, image
downloads, and the distribution metadata contract. Subsites own presentation and
deployment.
